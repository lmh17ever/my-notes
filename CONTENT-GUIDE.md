# CONTENT-GUIDE — конвенции базы знаний

Это справка для **любого ИИ-агента**, который развивает эту базу знаний.
Прочитай её целиком перед работой. Сайт рендерит только `src/content/`.

## Где что лежит

| Папка | Что это |
|---|---|
| `src/content/<категория>/<заметка>.md` | **Каноническая база знаний.** Её рендерит сайт. Категория = папка. |
| `inbox/` | **Хаос.** Новые записи, любые мысли вперемешку, можно всё в один файл. Твоя задача — разобрать это. |

## Категории

- Категория — это **папка** внутри `src/content/`. Ты **сам создаёшь** категории по мере надобности,
  не привязан к заранее заданному списку.
- Категория = предметная область: `postgresql`, `http`, `linux`, `docker`, `git`,
  `prompt-engineering`, `python`, `career`, `pet-project`, `general` и т.п.
- Если тема новая и заметка не вписывается ни в одну категорию — создай новую папку.

## Правила заметок

1. **Одна заметка = одна тема.** Из хаотичного файла выделяй атомарные блоки
   (определения, вопросы, конспекты, идеи) и клади каждый в свою заметку.
2. **Обязательный frontmatter** (YAML в начале файла):

   ```yaml
   ---
   title: "Краткое ёмкое название"
   summary: "Одно-два предложения: о чём заметка"
   tags: [тема1, тема2]
   status: active        # active | draft | archived
   date: 2026-08-13
   related: [slug-другой-заметки]   # необязательно
   featured: false       # необязательно, подсветить на главной
   ---
   ```

3. **Имя файла = slug** (kebab-case, латиницей): `planner-and-joins.md`.
4. `title` осмысленный, `summary` заполнен всегда — это заголовки/подписи карточек на сайте.
5. Содержимое — обычный Markdown. Код — в fenced code block с указанием языка:
   ````text
   ```sql
   SELECT * FROM ...
   ```
   ````
6. **Не выдумывай.** Сохраняй смысл исходной записи. Если это вопрос — оформи как вопрос
   (можно пометить `status: draft`), не выдумывай ответ.
7. **Не дублируй.** Перед созданием новой заметки проверь: может, новая запись дополняет уже
   существующую заметку? Тогда **дополни её**, а не создавай дубль.
8. **Связывай.** Если новая заметка связана с другой — добавь slug во фронтматтер `related`.

## Статусы

- `active` — готовая активная заметка (видна в обычных списках).
- `draft` — черновик / открытый вопрос (помечается на сайте, не пропадает).
- `archived` — устаревшее, хранится для истории.

## Рабочий цикл агента

1. Сканируй `inbox/` (один или несколько `.md`, хаотичный текст).
2. Разбей контент на атомарные блоки.
3. Для каждого блока реши: новая заметка / дополнить существующую / новая категория.
4. Создай/обнови файлы в `src/content/` с корректным frontmatter.

## Запрещено

- Не трогай код (`src/routes`, `src/lib`, конфиги) — только `src/content/` и `inbox/`.
- Не удаляй информацию бесследно.
- Не создавай пустые или однострочные заметки без смысла.
