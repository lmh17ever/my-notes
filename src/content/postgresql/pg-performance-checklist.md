Главный принцип:

> Сначала определить, какие операции будут частыми, потом выбирать структуру, индексы и настройки.

## Сценарии выбора

**Нужно быстро искать одну/мало строк** (по id или уникальному полю) → `Index Scan`, `CREATE INDEX ON users(id)`.

**Нужно получить много строк из большой таблицы** (например, 50% таблицы) → `Seq Scan`: индекс приведёт к миллионам переходов в Heap, последовательное чтение дешевле. Не всегда нужен индекс.

**Нужно получить много строк, но не всю таблицу** (500 тыс. из 100 млн) → `Bitmap Heap Scan` (собрать адреса → сгруппировать страницы → прочитать Heap).

**Фильтровать + сортировать + LIMIT**:

```sql
WHERE user_id = 10 ORDER BY created_at DESC LIMIT 20
```

- плохой индекс `(user_id)` → `Index Scan → Sort → Limit`;
- лучше `(user_id, created_at DESC)` → `Index Scan → Limit`.

Правило: если часто есть `WHERE + ORDER BY`, индекс должен учитывать оба.

## Создавать ли индекс

Задай вопросы:

- часто в `WHERE`? → индекс;
- в `JOIN`? → индекс на колонку соединения (`orders.user_id`);
- в `ORDER BY`? → индекс с правильным порядком;
- возвращает половину таблицы? → скорее нет.

## Порядок колонок в составном индексе

Правило: сначала равенство (`=`), потом диапазон (`<`, `>`, `BETWEEN`), потом сортировка.

```sql
WHERE user_id = 10 AND created_at > '2025-01-01'
```

Хорошо: `(user_id, created_at)`.

```sql
WHERE created_at > '2025-01-01'
```

`(user_id, created_at)` — плохо.

## Покрывающий индекс

Для запроса, который читает только часть колонок, можно использовать `INCLUDE`:

```sql
CREATE INDEX ... ON users(email) INCLUDE(name);
```

Тогда возможен `Index Only Scan` (не нужно идти в Heap).

## Почему Planner выбрал не индекс

1. Статистика: `ANALYZE;`, сравнить `rows` и `actual rows`.
2. Слишком много строк (индекс может быть хуже Seq Scan).
3. Настройки: `random_page_cost`, `effective_cache_size`, `work_mem`.

## Алгоритм если запрос медленный

```text
EXPLAIN ANALYZE
→ найти самый долгий узел
→ посмотреть actual time, rows, loops, Buffers
→ понять причину
→ изменить индекс / запрос / настройку
```

## Быстрая таблица выбора

| Условие | Выбор |
|---|---|
| 1 строка по ключу | Index Scan |
| много строк из небольшой части таблицы | Bitmap Scan |
| большая часть таблицы | Seq Scan |
| WHERE + ORDER BY + LIMIT | составной индекс |
| мало строк + JOIN | Nested Loop |
| большие таблицы + JOIN | Hash Join |
| уже отсортированные данные | Merge Join |
| GROUP BY, мало групп | Hash Aggregate |
| GROUP BY по отсортированным данным | Group Aggregate |
| много сортировки | проверить work_mem |
| Planner ошибается | проверить статистику |
| SSD вместо HDD | уменьшить random_page_cost |

Это уровень, достаточный, чтобы на backend-работе понимать, почему запросы работают быстро или медленно и что проверять первым.
