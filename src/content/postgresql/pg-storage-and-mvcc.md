## Таблица → страницы → строки

PostgreSQL хранит данные страницами:

```text
Table
 │
 ├── Page 1
 │    ├── Row
 │    └── Row
 │
 └── Page 2
      └── Row
```

Основные идеи:

- чтение идёт **страницами**, а не отдельными строками;
- страница обычно **8 KB**;
- стоимость запроса зависит от количества прочитанных страниц.

## MVCC

PostgreSQL не изменяет строку напрямую.

При `UPDATE` старая версия строки остаётся, создаётся новая:

```text
Было:       id=1, name='Alex'
После UPDATE: старый вариант остаётся, новый вариант создаётся
```

Каждая версия строки имеет:

- `xmin` — транзакция, создавшая строку;
- `xmax` — транзакция, удалившая/скрывшая строку.

## Visibility

Транзакция видит строку, если:

- строка создана до начала её снимка;
- строка не была удалена до её снимка.

Поэтому разные транзакции могут видеть разные версии одной строки.

## VACUUM

Проблема MVCC: при `UPDATE` старая версия строки остаётся.

`VACUUM`:

- удаляет ненужные версии;
- освобождает место;
- обновляет служебную информацию;
- помогает индексам.

## Visibility Map

`VACUUM` отмечает страницы как «all rows visible» (когда все строки страницы были видны на момент работы VACUUM и с тех пор страница не менялась):

```text
Page → all rows visible ✅
```

Это нужно для **Index Only Scan**:

- если страница помечена — можно брать данные только из индекса;
- если нет — нужно идти в Heap.
