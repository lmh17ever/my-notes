Выбор БД начинается не с вопроса «какая быстрее», а с вопроса:

> Как библиотекарь будет искать, хранить и изменять книги?

Для backend чаще всего выбор идёт между PostgreSQL, MySQL и MongoDB.

## 1. Есть ли связи между данными

- **Да** (пользователь → заказы → товары) → PostgreSQL / MySQL.
- **Нет, данные как самостоятельные документы** с разными полями → MongoDB.

## 2. Структура данных часто меняется

- **Редко** (заранее знаешь структуру: id, name, email, created_at) → PostgreSQL / MySQL.
- **Постоянно** (профиль обрастает новыми полями) → MongoDB.

## 3. Нужны сложные запросы

«Найти пользователей из Москвы, которые покупали товар X за месяц, отсортировать по сумме» → при частых таких запросах **PostgreSQL** (JOIN, GROUP BY, оконные функции).

Если запросы обычно «найти документ по ID» → подходит и MongoDB.

## 4. Нужна строгая целостность данных

Банк: снять деньги → уменьшить баланс → создать запись операции. Нельзя потерять операцию → **PostgreSQL/MySQL** (транзакции, ограничения, внешние ключи). MongoDB тоже имеет транзакции, но её основной подход другой.

## 5. Размер данных

- Обычный backend (тысячи–сотни миллионов строк) → **PostgreSQL/MySQL**.
- Очень большие распределённые системы (миллиарды документов) → могут выбирать MongoDB и др.

## 6. PostgreSQL или MySQL

- **PostgreSQL**: сложные запросы, аналитика, много связей, нужна расширяемость, хочешь глубже понимать базы.
- **MySQL**: простой CRUD, уже есть инфраструктура на MySQL, команда использует MySQL.

## Практическое правило

```text
Есть таблицы и связи? → нужны сложные запросы? → Да → PostgreSQL
                                                 → Нет → PostgreSQL или MySQL
Нет связей, данные как документы? → MongoDB
```

Для большинства новых backend-проектов безопасный выбор сегодня — **PostgreSQL**, потому что он покрывает больше сценариев и редко становится ограничением.
