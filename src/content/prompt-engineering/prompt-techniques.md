## Базовая структура промпта

- задача;
- контекст;
- ограничения;
- входные данные;
- ожидаемый результат;
- формат ответа;
- примеры.

Научиться понимать, какая информация действительно нужна модели.

## Инструкции и приоритеты

- system / developer / user instructions;
- явные и неявные требования;
- конфликтующие инструкции;
- scope инструкций, приоритеты;
- как уменьшать неоднозначность.

## Контекст

- что помещать в prompt, а что не помещать;
- контекстная перегрузка;
- релевантность информации;
- длинный контекст и потеря внимания;
- структурирование большого контекста.

Практика: давать модели большой набор информации и учиться выделять только необходимое.

## Few-shot prompting

- zero-shot / one-shot / few-shot;
- выбор хороших примеров;
- контрпримеры;
- форматирование примеров;
- когда примеры эффективнее длинных инструкций.

## Reasoning-задачи

- decomposition;
- пошаговое решение;
- промежуточные проверки;
- self-check;
- critique / revision;
- когда просить модель рассуждать, а когда хватает прямой инструкции.

Важно: не «выводить chain-of-thought», а правильно строить процесс решения задачи.

## Structured Output

- JSON, schemas, перечисления;
- обязательные поля, типы данных;
- validation;
- что делать при невалидном ответе.

Для backend особенно важно.

## Классификация и извлечение данных

```text
текст → LLM → структурированные данные
```

Задачи: classification, extraction, entity recognition, summarization, normalization.

## Prompting для генерации

- текст, код, SQL, документация, технические ответы, преобразование текста.

Главное — управление требованиями и форматом, а не литературное «написание промптов».
