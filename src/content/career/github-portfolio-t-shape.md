## Как делать НЕ надо

«Backend Developer: Python, Go, Rust, C#» + четыре одинаковых простых проекта → образ «поверхностного кодера»: прыгает по верхам, ни один язык не знает глубоко.

## Как надо: образ T-Shaped инженера

T-Shaped специалист:

- **вертикальная палочка «Т»** — глубокая специализация: в вашем случае Python (Django/DRF), проект на 15 000 строк, понимание продакшена;
- **горизонтальная черта «Т»** — широкий кругозор: умение подбирать правильный инструмент под задачу.

Логика для резюме (пример): «Я Python-разработчик, основной стек — Django. Когда в CRM возникла проблема с блокировкой сетевых потоков при отправке уведомлений, я написал микросервис на Go. Для автоматизации документации — утилиту на Rust (важна скорость парсинга и независимость от Python). Для графиков на Windows-компьютер директора — лёгкий GUI на C# (для десктопа хорош .NET)».

Такой подход показывает: понимание границ применимости технологий, умение учиться самостоятельно, прагматизм (экономия ресурсов сервера и денег бизнеса).

## Как работает найм

- **HR не читает код** — оценивает резюме по ключевым словам (стек) и результатам (работающий в продакшене сайт ценнее идеального мёртвого кода пет-проекта).
- **Тимлид** смотрит 1) README (архитектурная схема, описание связки Django+Go через Redis, запуск в Docker одной командой); 2) 1–2 случайных файла (разбивка на модули, понятные имена, нет хаоса).

## Тактика «витрина»

- Изолировать хардкор: Go-микросервис — в отдельной папке/репозитории, написанный идеально (обработка ошибок, логирование, комментарии).
- В README и резюме вести тимлида именно туда: «Основной монолит — Django, а архитектурно сложная и оптимизированная часть вынесена в микросервис на Go».

## Ответ про «мусорный» код

`15 000 строк` — это размер хорошего коммерческого MVP, и техдолг через него проходит у всех. Ответ на претензию: «Да, я знаю про это место. Код писался на раннем этапе, чтобы быстро проверить бизнес-логику и запустить CRM в продакшен. Проект живой. Сейчас у меня в бэклоге задача отрефакторить модуль и вынести часть на Go, как я уже сделал со службой уведомлений».

Для нанимающего это признак зрелости: бизнес нанимает не ради идеального кода, а ради работающих продуктов и умения управлять техдолгом.
