## Что вынесут на Go по мере роста

### Задача А: работа с внешними интеграциями (I/O-Bound)

Контекст: синхронизация остатков с десятками поставщиков по API, сборка сообщений из сотен чатов. Проблема Python: воркеры на Django/Celery жрут гигабайты памяти, зависают на сетевых таймаутах, пропускают обновления. Работа на Go: вынести парсер/синхронизатор в отдельный сервис, собирать данные горутинами в Redis, откуда Django забирает без напряжения.

### Задача Б: real-time шлюзы и шины событий (WebSockets)

Контекст: живой чат в CRM, трекер с движущимися курьерами. Проблема Python: удерживать 5–10 тысяч постоянных соединений тяжело. Решение: Go-микросервис, отвечающий только за удержание соединений с фронтендом, принимающий сообщения от Django и раскидывающий по клиентам.

### Задача В: агрегаторы логов и аудита (Audit Trail)

Контекст: запись каждого действия менеджера. Проблема: запись в БД при каждом клике «уложит» базу. Решение: Django выплёскивает логи в Redis асинхронно, сервис на Go забирает их, батчится и раз в минуту пишет в аналитическую БД (например ClickHouse).

## Где используется Rust

Rust в компаниях такого масштаба — точечно, как «турбо-буст» для Python: отдельный алгоритм (расчёт тарифов, тяжёлая фильтрация сотен тысяч строк, шифрование данных) переписывается на Rust и компилируется через **PyO3** в бинарный модуль `.so`/`.pyd`:

```python
from my_rust_module import calculate_tariffs
```

Быстро, а проект остаётся в привычном Django. Переписывать весь сервис на Rust — долго и ломает архитектуру.

## К какому будущему готовиться

В средних компаниях ждут «fullstack-бэкендера», который понимает и бизнес-логику, и системные ограничения. ~70% времени — понятный код на Python/Django. Но когда система упирается в сеть, многопоточность или память — уверенно брать Go и за пару дней собрать надёжный изолированный микросервис.

План (закрыть пробелы по HTTP/Linux/Docker, закрепить Django, пересесть на Go) готовит к реальным задачам рынка.
