Идеи для «полки будущего» — что написать как первый open-source трофей на Rust или Go. Это полноценные инструменты, решающие конкретную инженерную боль, а не «пет-проекты для галочки».

## Идея 1. Автоматический чистильщик базы Django от «мусорных» файлов

**Проблема:** в Django при удалении записи удаляется строка из БД, но физический файл (`FileField`/`ImageField`) на диске или в S3 остаётся навсегда. Проекты годами копят терабайты мусора; Python-пакеты для очистки медленные и грузят сервер.

**Что делает утилита (Go/Rust):** автономный CLI-сканер — подключается к MySQL, достаёт пути к реальным файлам, сканирует медиа-папку, находит файлы-сироты (есть на диске, но удалены из БД) и безопасно стирает, выводя отчёт и графики в терминал.

**Польза:** решает проблему, с которой сталкивается каждый проект на Django через 2–3 года. Полезно сисадминам и DevOps.

## Идея 2. Сверхбыстрый визуализатор логов SQL-запросов

**Проблема:** при отладке в Django включают логирование всех SQL (борьба с N+1). Читать простыню в терминале — боль.

**Что делает (Go/Rust):** лёгкий TUI-инструмент — слушает поток логов от Django, форматирует/подсвечивает SQL, группирует дубликаты, отмечает красным запросы дольше 50 мс.

**Польза:** TUI на ratatui (Rust) или bubbletea (Go) — большой тренд, стильно и нужно для ежедневной разработки.

## Идея 3. Dockerfile-оптимизатор для Python/Django

**Проблема:** написать идеальный Dockerfile для Python — искусство (кэш слоёв, multi-stage, уборка мусора pip).

**Что делает (Rust/Go):** анализирует `requirements.txt` / `poetry.lock` и текущий Dockerfile, указывает на ошибки безопасности (например запуск под root), автоматически переписывает Dockerfile, чтобы сборка была в ~3 раза быстрее, а образ весил минимально.

**Польза:** статический анализ в тренде; показывает понимание устройства слоёв Docker, а не просто `docker build`.

## Идея 4. Микросервис-прокси для генерации красивых PDF-документов

**Проблема:** в любой CRM нужна генерация счетов/актов/договоров с автозаполнением. В Django через reportlab/weasyprint это медленно, нестабильно и грузит CPU.

**Что делает (Go):** изолированный микросервис — Django шлёт HTML-шаблон + JSON, сервис (движок Chromium в headless-режиме) рендерит PDF со скоростью сотен штук в секунду.

**Польза:** готовый коммерчески ценный open-source микросервис, который разработчик на Django/Node/PHP может запустить рядом в Docker.

## Сравнение

| Проект | Язык | Кому полезен | Чему научит |
|---|---|---|---|
| Чистильщик файлов | Go или Rust | Django-разработчикам, DevOps | Работа с БД напрямую, файловая система |
| Визуализатор SQL | Rust (Ratatui) | всем Python-разработчикам | Парсинг текста, TUI |
| Docker-оптимизатор | Rust | DevOps, системные инженеры | Устройство слоёв Docker, статический анализ |
| PDF-генератор | Go | всему IT-сообществу | Сетевой бэкенд, конкурентность |
