## IP-адрес

**Что это:** адрес устройства в сети.

**Как привязан к интерфейсу:** один интерфейс может иметь несколько IP-адресов (IPv4 и IPv6).

**Команда:**

```bash
ip addr show ens192
```

**Пример вывода:**

```text
inet 185.250.180.136/24 brd 185.250.180.255 scope global ens192
```

- `185.250.180.136` — сам IP
- `/24` — маска подсети
- `brd 185.250.180.255` — широковещательный адрес
- `scope global` — адрес виден извне

## Маска подсети (CIDR)

**Что это:** делит IP-адрес на **сеть** и **устройство**.

**Зачем:** компьютер решает, отправлять пакет напрямую (в локальной сети) или через шлюз.

| Запись | Полная маска | Что под сеть | Что под устройства |
|--------|--------------|--------------|---------------------|
| `/8`   | `255.0.0.0`  | 1 число      | 3 числа (16 млн)    |
| `/16`  | `255.255.0.0`| 2 числа      | 2 числа (65 тыс)    |
| `/24`  | `255.255.255.0` | 3 числа   | 1 число (254)       |

**Правило:** если у двух адресов часть, отведённая под сеть, совпадает — они в одной локальной сети.

## Адрес сети и широковещательный адрес

- **Адрес сети** — начало диапазона (все биты устройства = 0).
- **Широковещательный** — конец диапазона (все биты устройства = 1).

**Примеры:**

| Адрес | Маска | Сеть | Широковещательный |
|-------|-------|------|--------------------|
| `185.250.180.136/24` | `/24` | `185.250.180.0` | `185.250.180.255` |
| `10.5.0.50/16` | `/16` | `10.5.0.0` | `10.5.255.255` |
| `10.0.0.5/8` | `/8` | `10.0.0.0` | `10.255.255.255` |

## Количество сетей vs количество устройств

**Важно не путать:**

- **Количество сетей** с маской `/X` — сколько разных «улиц» может существовать.
- **Количество устройств** внутри одной такой сети — сколько «домов» на одной улице.

| Маска | Сколько таких сетей в мире | Устройств в одной сети |
|-------|----------------------------|-------------------------|
| `/8`  | 256                        | ~16,7 млн               |
| `/16` | 65 536                     | ~65 тыс                 |
| `/24` | ~16,7 млн                  | 256                     |

## Как определить локальную сеть (главное правило)

1. Посмотри на маску.
2. Определи, сколько чисел отведено под сеть.
3. Сравни эти числа у двух адресов.
4. Если совпадают → одна локальная сеть → пакет напрямую.
5. Если не совпадают → разные сети → нужен шлюз.

## Команды

| Команда | Что делает |
|---------|------------|
| `ip link show` | Показать все интерфейсы и их состояние |
| `ip addr show ens192` | Показать IP-адреса у конкретного интерфейса |
| `ip a` | Сокращение для `ip addr` |

## Где пригодится в backend-разработке

IP-адресация — основа, на которой строится всё сетевое взаимодействие в бэкенде.

### Реальные сценарии

#### Сценарий 1: Порт занят (0.0.0.0 vs 127.0.0.1)

Приложение не стартует с ошибкой `Address already in use`. Проверка `ss -tulpn | grep 8080` показывает процесс на `0.0.0.0:8080`.

**Важно:** `0.0.0.0:8080` и `127.0.0.1:8080` — это **разные сокеты**, но если кто-то слушает на `0.0.0.0:8080`, то `127.0.0.1:8080` **тоже занят**, потому что `0.0.0.0` включает все интерфейсы, включая `127.0.0.1`.

#### Сценарий 2: Разрешение имён (DNS) в коде

```python
import requests
response = requests.get('https://api.example.com/v1/users')
```

Под капотом: `getaddrinfo()` → ОС смотрит `/etc/hosts`, потом DNS → получает IP → открывает сокет на этот IP и порт 443. Если DNS не работает, код не сможет найти IP.

#### Сценарий 3: Белые списки IP (CORS, firewall, доступы)

```text
Allow from 192.168.1.0/24
Deny from all
```

или в конфиге Nginx:

```nginx
allow 10.0.0.0/8;
deny all;
```

Чтобы это написать, нужно понимать IP, маску подсети и как ограничивать диапазоны.

#### Сценарий 4: Реальный IP клиента через прокси

Когда запросы идут через прокси (Nginx), в логах виден `127.0.0.1` для всех запросов. Чтобы узнать реальный IP: настроить Nginx передавать заголовок `X-Forwarded-For` и в коде читать его, а не `REMOTE_ADDR`.

#### Сценарий 5: Разделение сред (dev / staging / prod)

- локальная среда — `127.0.0.1`
- тестовая среда — `10.0.0.5`
- продакшн — `185.250.180.136`

Конфиги подтягивают разные настройки в зависимости от IP или имени хоста.

#### Сценарий 6: IPv6

Если сервис слушает только на `0.0.0.0` (IPv4), он не примет IPv6-запросы. Правильный вариант — слушать на `::` (все IPv6 и IPv4) или на `0.0.0.0` + `::` отдельно.

### Что даёт знание IP

| Навык | Когда пригодится |
|-------|-------------------|
| Проверить, какой IP у интерфейса | При деплое и диагностике |
| Проверить, слушает ли приложение на `0.0.0.0` или `127.0.0.1` | Когда сервис не отвечает снаружи |
| Понимать маску подсети | Когда настраиваешь доступы или белые списки |
| Отличать публичный IP от приватного | Когда работаешь с облаками, VPN, Docker |
| Понимать про IPv6 | Когда внезапно перестают приходить запросы |
| Читать логи и понимать, откуда пришёл запрос | Всегда, ежедневная задача |

### Итог

Знание IP-адресации даёт: возможность настраивать доступы и безопасность; понимание, как работает DNS и почему запросы могут падать; инструменты диагностики — почему приложение не отвечает, почему логи показывают не тот IP.
